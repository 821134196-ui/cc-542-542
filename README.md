# 影城放映机灯泡管理系统

零依赖（仅 Python 3 标准库）：SQLite 存设备状态，本地 `data/photos/` 存亮度照片，
放映机读数由模拟适配器返回。

## 一条命令启动

```bash
python3 run.py            # 建库 → 写入含临界寿命样例的种子数据 → http://127.0.0.1:8000
python3 run.py --reset    # 删库重新初始化
```

种子样例：**2 号厅灯泡 487/500h（临界寿命）**，IMAX 厅 512/500h（超阈值，需主管批准），
IMAX 厅首次计时器重置失败、备件 `B2000-DEF01` 为缺陷件（试映亮度不足）、
备件 `X999-OTHER` 型号不符。

## 测试

```bash
python3 -m unittest discover -s tests -t .
```

覆盖：时长累计、维修互斥、备件匹配、放行权限，以及已拆灯泡禁用、超阈值审批、
步骤顺序、计时器重置失败处置、试映亮度不足阻断、中途取消。

## 交付物与页签

| 交付物 | 位置 |
|---|---|
| 设备台账 | 「设备台账·寿命预测」：放映机型号、灯泡序列号、累计点亮小时、厂家阈值 |
| 寿命预测 | 同上：剩余小时、按排期可放场次、预计触阈时间 |
| 换灯工单 | 「换灯工单」：固定编号步骤 1 断电 → 2 冷却 → 3 安装 → 4 对焦 → 5 试映 |
| 试映记录 | 「试映记录」：前后亮度数值成对展示 + 本地亮度照片 |
| 场次影响 | 「异常·场次影响」：受影响/延误/取消场次 |
| 放行审批 | 「放行审批」+ 工单内签署 |

## 业务规则

- **时长累计**：场次完成后按场长累计点亮小时，设备读数回写台账。
- **覆盖判断**：排场后对比剩余寿命与场长（余量 <30 分钟为临界）。
- **维修互斥**：同一放映机同一时间仅一名技术员可占用维修窗口（DB 部分唯一索引兜底）。
- **备件匹配**：新灯型号须与机型要求一致且为备件状态；**已拆下的灯泡不得重新标为在用**。
- **超阈值设备**：必须由放映主管批准方可临时使用（默认 24h 有效）。
- **放行权限**：审批人必须是放映主管，且**换灯人不能签署本人工单**。
- **六类异常处置**：异常熄灯 / 计时器重置失败 / 备件型号不符 / 换灯中途取消 /
  试映亮度不足 / 场次延误，均登记闭环；计时器与亮度异常未处置前工单不得放行。

## 结构

```
run.py              一条命令启动
cinema/
  db.py             SQLite schema（含维修窗口互斥唯一索引）
  adapter.py        模拟放映机适配器（小时/亮度/计时器重置，可注入失败）
  services.py       全部业务规则
  seed.py           种子数据（含临界寿命样例）
  photos.py         本地亮度照片生成
  server.py         stdlib HTTP 服务与 API
static/             影院黑 + 白字 + 金色状态标记
tests/              unittest
data/               运行时生成：cinema.db 与 photos/
```
